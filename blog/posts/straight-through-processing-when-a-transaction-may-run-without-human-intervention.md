My last two pieces showed where data still changes media and how interfaces can route them directly to where they belong. The remaining question: when may a transaction run without any human intervention?

The answer is in the GoBD.

Paragraph 108 defines: "Program-generated transactions are transactions created by program-controlled routines without manual input." The law does not distinguish between manual and automated recording – Section 146 of the German Fiscal Code (AO) only requires that the principles of proper bookkeeping are observed. IDW RS FAIT 1 (paragraphs 42–45) also clarifies that program-controlled transactions are permissible as long as the underlying logic is documented.

In short: the law permits straight-through processing. Practice struggles with it.

An example: a rent payment of €1,250.00 is debited monthly. Amount, payee and reference are identical every month. Yet the document is still received, opened, reviewed, assigned to an account, and booked manually. The accounting software could determine the correct posting based on amount, reference and prior-year data. The bookkeeper would only need to intervene when something deviates.

This is exactly what the DATEV automation services do: they analyse bank statements and invoices, match them against booking history, and deliver booking suggestions. The AI learns from corrections. The suggestions are never error-free – but that is not an argument against automation; it is an argument for risk-based review of exceptions.

The benefit is not total automation. It lies in the bookkeeper spending their time where their judgement is needed – on unusual transactions, new business events, complex cases. The machine handles the routine.

Straight-through processing is not a future scenario. It is permitted today, the technology is here, and the 2025 GoBD have set the course. Separating routine from exception frees up time for the cases that need real judgement.
